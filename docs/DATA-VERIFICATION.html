数据真实、可追溯、可复核

所有进入报告的 Sorftime 数据，都要保留工具、参数、通道、观测时间和原始响应哈希。没有证据，就不把估算写成事实。

证据类型4 层
完整性校验SHA-256
决策门decision-grade
支持通道MCP + CLI

一条数据从接口到报告

① 采集

MCP 原始响应保存为 JSON；CLI 用 capture-cli 直接采集。

② 落账

记录工具、参数、阶段、通道、观测时间、原始响应。

③ 哈希

对规范化 JSON 计算 SHA-256，后续改动即可发现。

④ 校验

校验时间、阶段、工具、重复 ID 和哈希一致性。

⑤ 决策

只让 observed 记录进入 Go/No-Go；估算单独标注。

CLI 自动采集

python3 ../evidence_ledger.py capture-cli \
  --ledger data/evidence/ledger.jsonl \
  --endpoint ProductRequest \
  --stage G3 \
  --params '{"asin":"YOUR_ASIN"}' \
  --domain 1

不手工抄数字，不让报告和接口响应脱节。

MCP 响应落账

python3 ../evidence_ledger.py record \
  --ledger data/evidence/ledger.jsonl \
  --tool product_detail \
  --channel mcp --stage G2 \
  --params '{"asin":"YOUR_ASIN"}' \
  --input response.json

保存原始响应；需要加工时另记 derived 记录。

决策前校验

python3 ../evidence_ledger.py verify \
  --ledger data/evidence/ledger.jsonl \
  --decision-grade \
  --require-stage G2 --require-stage G3 --require-stage G4 \
  --require-tool ProductRequest \
  --fresh-hours 168

任一时间异常、哈希不匹配、阶段缺失或工具缺失都会返回非 0，不能继续写成“已验证”。

五种证据，不能混写

类型含义能否直接支撑 Go/No-Go
observedSorftime 或公开源直接返回可以，仍需业务质量门
derived基于 observed 计算，写明公式和来源可以，但必须可复算
estimate估算、假设、缺证据的默认值不可以单独支撑精确决策
inference判断、解释、机会假设不可以当作事实
missing工具返回空数据、空列表或 No data available只能写成数据缺口

真实性边界

这套机制解决什么

捕获后是否被改动；数字来自哪个工具和参数；报告是否把估算误写成事实；其他人能否按命令复核。

这套机制不替代什么

不替代 Sorftime 凭证、服务端真实性、官方专利文件或律师意见。哈希不是区块链，也不是上游真实性证明。
