# VOC 分析方法论

## 一、核心原则：痛点严重度指数

不要做简单的"高频词计数"。一个低频但几乎全部绑定差评的痛点（如"着火"），比高频但多在中性评论中提及的词（如"价格"）更值得关注。

```
Severity Index = 提及频次得分 × 评分负相关系数
```

- 低频但强负相关（如"螺丝松了"仅出现3次但全是1星）→ 排名高于高频但多在中性评论中出现的词
- 频次 < 5 的关键词不自动丢弃——需结合评分负相关性判断

---

## 一-B、数据质量前置门

在分析前先跑 `scripts/review_quality.py`：

- `Customers Say`：检查 `positive + negative <= mention`；不满足的主题标 INVALID，不得进入排序。
- 评论：先按标题+正文去重，再按目标变体过滤。
- 结果必须记录：原始评论数、去重后数量、目标变体数、其他变体数、未标变体数。
- 未标变体不得混入目标 SKU 的频次和负面率。

## 二、分析流程

### Step 1：数据采集
- **评论**：`ProductReviewsQuery` 拉取好评(4-5星)和差评(1-3星)，每个 ASIN 建议拉 2-3 页（200-300条）
- **AI 摘要**：`ProductCustomersSay` 获取 Amazon 自动生成的评论总结
- **Q&A**：`AlexaQuestionsQuery` 拉取买家预设问题
- **社媒**：`reddit_post_search` 搜索相关 Reddit 讨论

### Step 2：差评痛点抽取（T2a 批分析）

从差评中提取高频痛点（频次 ≥ 2 次），每条记录：

```json
{
  "pain_point": "漏水瓶盖",
  "frequency": 5,
  "evidence_quote": "the lid leaks everywhere",
  "asin": "B0XXXX"
}
```

**痛点分类体系**：
| 类别 | 示例 |
|------|------|
| 功能缺陷 | 漏水、不充电、自动关机、噪音大 |
| 材质/做工 | 廉价塑料、边缘锋利、接缝明显、易碎裂 |
| 尺寸/规格 | 尺寸不符、太小、不兼容、太重 |
| 说明书/包装 | 说明书不清楚、缺少配件、包装破损 |
| 预期落差 | 没有宣传的功能、续航差、效果一般 |
| 物流/服务 | 发货慢、客服不回复、退货难 |

### Step 3：好评卖点抽取

从好评中提取高频卖点（频次 ≥ 2 次）：

```json
{
  "selling_point": "轻便易携",
  "frequency": 8,
  "evidence_quote": "super light and easy to carry",
  "asin": "B0XXXX"
}
```

### Step 4：使用场景提取

从好评中提取典型使用场景（场景 + 用户类型）：

```json
{
  "scenario": "每日通勤",
  "user_type": "上班族",
  "frequency": 6,
  "evidence_quote": "perfect for my daily commute to work",
  "asin": "B0XXXX"
}
```

### Step 5：跨 ASIN 汇总（T2b）

- 合并不同 ASIN 的同主题痛点，frequency 累加
- 保留 2-3 条不同 ASIN 的原文证据
- 按 frequency 降序取 Top 10

---

## 三、严重度指数计算方法

对每个痛点关键词：
1. 统计在差评中的提及次数（freq_neg）和好评中的提及次数（freq_pos）
2. 计算负相关系数 = freq_neg / (freq_neg + freq_pos)
3. Severity Index = log(1 + freq_neg) × 负相关系数

**解读**：
- **Severity > 0.6**：功能性硬伤（漏水/断裂/不兼容）→ 必须修复
- **Severity 0.3-0.5**：跨多个竞品一致出现的低频痛点 → 差异化机会，先解决者赢
- **Severity 突增**：3个月内从0.2涨到0.6 → 批次质量问题或供应商换料

---

## 四、Q&A 分析方法

Alexa Questions 反映了买家在下单前最关心的问题：

1. **高频问题提取**：哪些问题被反复提问 → listing 中应直接回答
2. **AI 回答质量评估**：Amazon AI 的回答是否准确反映产品实际表现
3. **预期管理**：如果 Q&A 中买家期望的功能与实际不符 → 产品描述需要修正

---

## 五、Reddit 社媒舆情

通过 `reddit_post_search` 和 `reddit_post_request`：
- 发现 Amazon 评论区之外的真实用户讨论
- 捕捉"还没上 Amazon 但已经在 Reddit 讨论"的需求信号
- 识别品牌口碑风险（产品在 Reddit 上被吐槽的具体问题）

---

## 六、输出规范

### 语言规则
- **痛点/卖点/场景/用户类型**：用**中文**概括描述
- **evidence_quote**：**必须 100% 原文复制**（英文原评论），不翻译、不改写
- ASIN/标题/端点名等标识符保留英文

### 报告章节
1. 调研概览（类目/站点/ASIN数/样本量）
2. 竞品清单（ASIN/标题/月销/评分/评论数）
3. Top 10 痛点（表格：中文描述 | 频次 | 涉及ASIN数 | 原文证据2-3条）+ 段落小结
4. Top 10 卖点（同上格式）+ 段落小结
5. Top 10 使用场景（场景 | 用户类型 | 频次 | 原文证据）+ 段落小结
6. Q&A 洞察（高频问题 + 建议回答方向）
7. 社媒舆情摘要
8. 结论与建议（改进机会 + 营销卖点 + 人群定位）

---

## 七、风险提示

- 评论数据时效性很重要——>6个月的评论可能反映已修复的旧问题，指数计算中降权
- 负面情绪不等于市场机会——有些痛点是物理极限（如"耳机不够小"），设计改进无法解决
- 评论数 < 50 的 ASIN 样本偏差大，结论仅供参考
- Amazon 评论存在删除和刷评——新品期异常评分分布需警惕
- 差评率被刷好评稀释时，Severity Index 会被低估，需结合总评论量交叉验证
